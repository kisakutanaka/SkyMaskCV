# SkyMaskCV

モバイルブラウザ上で、カメラ映像から**空だけをリアルタイムに分離**する実装。
CNN を使わず、古典的なコンピュータビジョンの手法だけで構成しています。

**デモ**: https://kisakutanaka.github.io/SkyMaskCV/

左に元映像、右に分離結果を並べて表示します。入力は同梱の動画・静止画のほか、
カメラ（HTTPS が必要なので GitHub Pages 上でのみ利用可）に切り替えられます。
「怪獣合成」は空のレイヤーに怪獣を挟んで建物に隠れさせるモード、
「空塗りつぶし」は空を単色で塗るモードです（マスクの粗の確認に使えます）。

## 速度

M 系デスクトップで **4.8 ms/frame**（分離処理のみ。フレーム全体では約 11ms）。
処理は 180×320 で行い、縮小・拡大は `drawImage` 経由で GPU に任せています。
WebGL も WASM も使っていません。

フレーム全体には `getImageData` による GPU からの同期読み戻しが含まれ、
実測ではそれが分離処理より高くつきます。削る必要が出たら、定数を詰めるより
処理解像度を下げるほうが効きます（転送量も一緒に減るため）。

## 手法

薄暮と曇天では、空を見分ける手がかりが**入れ替わります**。

| | 青優勢度 `(B-R)/(B+R)` | 輝度 |
|---|---|---|
| 薄暮: 空 / 地上 | **+0.47 / −0.26** | 73 / 72 ← 使えない |
| 曇天: 空 / ビル | +0.021 / +0.014 ← 使えない | **165 / 115** |

そのため固定しきい値では必ずどちらかで破綻します。代わりに
**画面上端の画素から「この空の見え方」を推定し、そこからの距離で判定**します。

```
シード = 上端10%行のうち 局所σ/輝度 < 0.045 の画素
  bdRef = 青優勢度の中央値   vRef = 輝度の中央値

空 =  |青優勢度 - bdRef| < 0.25
  かつ |輝度     - vRef|  < 42
  かつ 局所σ / 輝度 < 0.045
```

滑らかさの判定で局所σを**輝度で割っている**のは、テクスチャの振幅が明るさに
比例するためです。絶対値で切ると明るい空ほど不利になります。青優勢度を
`(B-R)/(B+R)` という比にしているのと同じ理由です。

各軸を AND で繋ぐと、**差のない軸は条件を素通りして黙る**ため、
どちらの手がかりが効くかをシーンが自分で決めます。判定に分岐はありません。

空は1組の代表値では表せないこともあります。青空に白い雲が浮かぶ構図では、
青空（実測 輝度113 / 青優勢度0.37）と雲（輝度189 / 0.07）が離れすぎていて
同時には囲えません。そこで**空と判った領域の縁から次のモードを拾って足します**。
縁に接していることを求めるのが肝で、これがないと空と地続きでない明るい面
（白い壁など）を拾います。実測では3回で収束します。

処理は2段構成です。

1. **粗パス (90×160)** — どこが空かという「面」を決める。しきい値判定 →
   オープニング → クロージング → 上端に接する連結成分の抽出 → 穴埋め
2. **精緻化パス (180×320)** — 粗マスクの境界の帯だけを実画素で判定し直す。
   帯の外は粗マスクを使うので、連結性と穴埋めの結果が保たれる

帯の中では覆す方向で基準を変えます（ヒステリシス）。実測では
**非空→空 の覆しは 81.8% が正しいのに、空→非空 は 38.5% しか正しくない**ため、
空を削るほうにだけ `keepTol` 倍の強い証拠を要求します。建物は倍にしても
許容外に出るので、稜線に吸着する働きは保たれます。

## パラメータ

較正は Open Images から取った 4236 枚（`skyseg` のラベル付き）で行っています。
train 600 枚で決めて val 335 枚で検証し、さらに `img/` の元素材5枚で
劣化しないことを確認する手順です。

| パラメータ | 既定 | 何を決めるか | 動かすと |
|---|---|---|---|
| `texRadius` | 2 | 局所σを測る窓の半径。粗解像度なので 5×5 画素 | 小さいと細かいノイズに反応し、大きいと細い構造を見逃す |
| `texMaxRel` | 0.045 | 滑らかさの上限。局所σを輝度で割った相対値 | 上げるほど構造のある雲を拾えるが、建物の壁面も拾い始める |
| `seedRowRatio` | 0.10 | 空の見えを推定するのに使う画面上端の割合 | 0.2 は train で改善し val で悪化した（過適合）ので上げない |
| `minSeedCount` | 50 | これ未満なら「空が写っていない」と判断し全0を返す | 下げると一様で明るい壁を空と誤認しやすい |
| `bdTol` | 0.25 | 青優勢度がシードからどれだけ離れてよいか。薄暮で効く軸 | 0.35 以上は飽和して変化しない。0.15 で mIoU −0.015 |
| `vTol` | 42 | 輝度がシードからどれだけ離れてよいか。曇天で効く軸 | 60 で適合率 −0.03（建物を飲む）。25 で再現率 −0.08 |
| `openRadius` | 1 | オープニングの半径。孤立した誤検出を削る | 2 にすると 2r+1 画素より細い空の筋が消える |
| `closeRadius` | 4 | クロージングの半径。空に入った切れ込みを橋渡しする | `bandRadius` を超えると境界がブロック状に残る |
| `minAreaRatio` | 0.01 | この割合に満たない連結成分は空と見なさない | 0.003 で再現率 +0.01 / 適合率 −0.01 |
| `bandRadius` | 4 | 高解像度で境界を引き直す帯の半径 | 3 にすると境界の未精緻化が 3-8% から 5-16% に増える |
| `modeReach` | 4 | 次のモードを探す範囲。マスクの縁から粗解像度で何画素まで見るか | |
| `modeMinCount` | 20 | 次のモードを認めるのに必要な候補画素数 | 50 だと雲の縁の候補が足りず第2モードが作られない |
| `modeRounds` | 3 | モードを継ぎ足す最大回数 | 0 で単一モード（従来の挙動）。3 で収束する |
| `keepTol` | 2.0 | 境界帯で「空を維持する側」の許容値の倍率 | 1 にすると雲の縁や空の諧調で境界が切れる。集計指標には出ず、効くのは見た目 |

**mIoU だけで較正しないこと。** このデータセットの平均は「空が大きく写った
易しい画像」に支配されるため、判定を緩めると mIoU は上がります。しかし
**建物が空になる誤りは、空を取りこぼす誤りより遥かに目立ちます**。実際、
定数を mIoU 最良に振り直すと mIoU +0.025 と引き換えに適合率が 0.926→0.867 に
落ち、曇天の画像でビル本体を丸ごと飲みました。適合率と再現率を分けて見ます。

| | mIoU | 適合率 | 再現率 |
|---|---|---|---|
| val 335枚 | 0.786 | 0.921 | 0.840 |
| train 3901枚 | 0.782 | 0.950 | 0.817 |

## 構成

```
src/skyMask.ts   すべての処理。純粋関数のみで DOM に依存しない
index.html       デモページ。canvas の配線と合成だけ
img/             テストソース
tools/           評価ハーネス（下記）
dist/            tsc の出力（追跡していない）
```

ビルドは `npx -y -p typescript tsc` のみ。バンドラもフレームワークも使いません。
GitHub Pages へは `.github/workflows/pages.yml` が push のたびにビルドして配信します。

ローカルで動かす場合:

```sh
npx -y -p typescript tsc
python3 -m http.server 8766
```

カメラ入力は HTTPS か localhost でのみ使えます。

## 評価

`dataset/`（追跡していない）に Open Images の画像と `labels_skyseg` を置いて実行します。
ラベル PNG は R チャンネルが空マスクです。

```sh
python3 tools/prep.py val  tools/out/val      # JPEG を raw RGBA に展開
python3 tools/gt.py   val  tools/out/val      # ラベルを raw の 0/1 に展開
node    tools/eval.mjs     tools/out/val      # dist/skyMask.js を走らせて採点
```

**Python で再実装せず、出荷している `dist/skyMask.js` をそのまま走らせます。**
参照実装を別に持つと実装ドリフトが起きるためです。

### 回帰セット（`img/` の元素材）

`img/` の素材自身にもラベルを起こしてあり、これが回帰テストになります。
データセットの平均は「空が大きく写った易しい画像」に支配されるため、
**データセットの mIoU が上がっても、このアプリが狙うシーンで劣化していないか**を
別に確認する必要があります。

| | mIoU | 適合率 | 再現率 |
|---|---|---|---|
| 回帰セット 19枚 | 0.928 | 0.963 | 0.961 |

弱いのは動画の後半、カメラがパンして構図が変わる区間です。

ラベルは隣の SkySegmentation リポジトリの U-2-Net 教師で起こします。
`img/` から作り直す手順:

```sh
# 静止画2枚と動画の20フレームおきを dataset/images/scenes/ に書き出す
python3 tools/scenes.py
# 教師モデルでラベルを起こす（19枚で約20秒）
../SkySegmentation/tools/.venv/bin/python \
  ../SkySegmentation/tools/pseudo_label_skyseg.py \
  ../SkySegmentation/dataset/skyseg.onnx \
  dataset/images/scenes dataset/labels_skyseg/scenes
# 採点
python3 tools/prep.py scenes tools/out/scenes
python3 tools/gt.py   scenes tools/out/scenes
node    tools/eval.mjs      tools/out/scenes
```

**ラベルは人手の正解ではなく教師モデルの擬似ラベルです。**
教師自身の誤りは含まれるので、絶対値ではなく変更前後の差を見る用途に使います。

## 既知の限界

- 空が画面上端に接していることを前提にしている。シードが取れなければ空マスクは
  空集合になる（誤検出するよりは安全側に倒す設計）
- 上端が一様で明るい壁に占められると、それを空としてシードしてしまう
- 粗解像度で1画素未満の細い構造（アンテナなど）は空に飲まれる
- 傾いた稜線は約4画素の階段になる（処理解像度の量子化）
- 定数は「薄暮」「曇天」の2条件で較正済み。快晴の青空・夜空・夕焼けは未検証
- 時間方向の平滑化は未実装のため、動画ではフレーム間のちらつきが残る
- 空と構造物の境界が元々曖昧な構図（霞んだ街並み、空を映す青いガラスのビル）
  では、モードの継ぎ足しが構造物側へ歩いて飲み込む。歩ける距離に上限を設けて
  いないため。上限を付けると雲まで届かなくなるので、こちらを許容している
